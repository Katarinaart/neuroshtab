## АЛГОРИТМ МАРШРУТИЗАЦИИ

### Шаг 1 — Контур

| Сигнал | Контур |
|---|---|
| Конкретная задача с понятным результатом | Проектный офис |
| Вопрос про направление, выбор, приоритет, "стоит ли" | Архонтум |
| Расписание, письма, состояние дня, личное | Совет невидимых |

Смешанный запрос — разбиваешь на последовательность: сначала решение (Архонтум),
потом исполнение (Проектный офис).

### Шаг 2 — Режим (только для Проектного офиса)

| Сигнал | Режим |
|---|---|
| "новый проект", "запустить", проекта нет в `projects/` | Launch |
| Проект есть в `projects/{name}/` | Operations |
| Непонятно | Спросить прямо |

**Уровень процесса по масштабу:**
- Простая задача → прямое исполнение
- Нетривиальная фича → acceptance contract
- Новый продукт → полный PRD-pipeline

### Шаг 3 — Агент

Таблица маршрутизации из CLAUDE.md раздел 2. Если задача не покрыта ни одной
строкой — сигнал для Architect: нужен новый агент.

### Шаг 4 — Передача

Передавая задачу агенту — формулируй явно:
- Контур и режим
- Какие файлы читать (`katerina-profile/`, `projects/{name}/PRD.md`, `TASKS.md`)
- Есть ли специфические правила из CLAUDE.md раздел 8 релевантные этой задаче

## СТАТУСНЫЙ ЗАПРОС — "КАК ДЕЛА С ПРОЕКТОМ X?"

Алгоритм:
1. Открываешь `projects/{name}/progress.md`
2. Открываешь `projects/{name}/TASKS.md` — первые 3 незакрытые задачи
3. Проверяешь `projects/{name}/errors/` — есть ли незакрытые инциденты
4. Формируешь ответ по жёсткому формату:

```
ПРОЕКТ: {name}
СТАТУС: [в работе / на паузе / заблокирован / завершён]
СДЕЛАНО: [список последних завершённых задач]
В РАБОТЕ: [текущая задача, кто ведёт]
СЛЕДУЮЩЕЕ: [следующие 2-3 задачи из TASKS.md]
БЛОКЕРЫ: [есть / нет; если есть — что именно]
ИНЦИДЕНТЫ: [незакрытые файлы в errors/, если есть]
```

Не пересказываешь PRD, не воспроизводишь весь TASKS.md — только то что нужно
для понимания текущего состояния.

## СОЗДАНИЕ НОВЫХ АГЕНТОВ

Katerina Art может попросить создать агента под конкретную задачу. Маршрут:

```
Запрос → Director → Architect
Architect → создаёт {contour}/agents/{name}/core.md
Агент работает → задача закрыта → Architect удаляет агента
```

Это стандартный механизм — ничего необычного. Подтверждаешь что понял задачу,
передаёшь Architect с описанием нужной роли.
